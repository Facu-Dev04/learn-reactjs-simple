## Next js y sus ventajaes. 

- Next js es un marco de trabajo de React js para poder optimizar los tiempos de desarrollo adquiriendo un set de herramientas que nos permiten crear aplicaciones web de manera más rápida y eficiente. 

## Ventajas de Next js

- **Renderizado del lado del servidor (SSR)**: Next.js permite renderizar páginas en el servidor, lo que mejora el rendimiento y la optimización para motores de búsqueda (SEO).
- **Generación de sitios estáticos (SSG)**: Next.js puede generar sitios web estáticos durante el tiempo de construcción, lo que resulta en tiempos de carga más rápidos y mejor rendimiento.
- **Rutas automáticas**: Next.js utiliza un sistema de enrutamiento basado en
    archivos, lo que facilita la creación de rutas sin necesidad de configurar un enrutador manualmente.
- **Sin configuración**: Next.js viene con una configuración predeterminada que permite a los desarrolladores comenzar rápidamente sin necesidad de configurar herramientas como Webpack o Babel.
- **SEO optimizado**: Next.js facilita la creación de aplicaciones web optimizadas para motores de búsqueda, lo que mejora la visibilidad en línea.
- **Enrutamiento dinámico**: Next.js permite crear rutas dinámicas fácilmente, lo que es útil para aplicaciones con contenido variable.
- **Soporte para API**: Next.js permite crear API directamente dentro de la aplicación,

## Como hemos trabajado hasta ahora?

- **El Cliente** se refiere al navegador web en el dispositivo envia la solicitud a un servidor web para obtener recursos como páginas HTML, imágenes, archivos CSS y JavaScript.

- **El Servidor** es una computadora o sistema que almacena, procesa y entrega recursos y servicios a otros dispositivos a través de una red, como Internet.

- **Paginas Estáticas** son páginas web que se entregan al navegador tal como están almacenadas en el servidor, sin modificaciones dinámicas. Estas páginas son rápidas de cargar y fáciles de almacenar en caché, ya que no requieren procesamiento adicional en el servidor.

- Ventajas: 
    - Rápidas de cargar.
    - Fáciles de almacenar en caché.
    - Simples de implementar y mantener.
- Desventajas:
    - Contenido fijo que no cambia según el usuario.
    - Difíciles de actualizar si hay mucho contenido.
    - Limitadas en funcionalidad dinámica.  
    - No se puede repetir el uso de componentes.

#### Ejemplo de Paginas Estáticas:

- Esto seria como tener 3 refigrigeradores diferentes (3 paginas HTML diferentes) para cada tipo de helado (de chocolate, de vainilla y de fresa). Cada vez que alguien quiere un helado, tiene que ir al refrigerador específico para ese sabor.
- Que pasa si quiero un helado de chocolate con chispas de colores? Necesitaria un nuevo refrigerador para ese sabor especifico.
- Esto lo que genera es mucha redundancia y desperdicio de recursos.

## SPA (Single Page Application)

- Una SPA es una aplicación web o sitio web que interactúa con el usuario mediante la reescritura dinámica de la página actual en lugar de cargar páginas enteras desde el servidor. Esto proporciona una experiencia de usuario más fluida y rápida, similar a la de una aplicación de escritorio.

### Ventajas:
    - Experiencia de usuario fluida y rápida.
    - Menor carga en el servidor.
    - Mejor para aplicaciones interactivas.

### Desventajas:
    - SEO puede ser un desafío.
    - Tiempo de carga inicial más largo.
    - Complejidad en la gestión del estado y la navegación.

## CSR (Client Side Rendering)

- El renderizado del lado del cliente (CSR) es una técnica en la que el contenido de una página web se genera y se muestra en el navegador del usuario utilizando JavaScript, en lugar de ser procesado y renderizado en el servidor antes de enviarse al cliente. En CSR, el servidor envía una página HTML básica junto con archivos JavaScript que contienen la lógica para construir y actualizar el contenido dinámicamente en el navegador.

### Ejemplo 

- Aca mismo estamos usando un solo refrigerador (una sola pagina HTML) para todos los sabores de helado. Cuando alguien quiere un helado, el refrigerador (la pagina HTML) usa ingredientes (JavaScript) para preparar el helado en el momento, según lo que la persona quiera.

### Ventajas:
    - Interactividad mejorada.
    - Menor carga en el servidor.
    - Desarrollo más rápido con frameworks modernos.

### Desventajas:
    - SEO puede ser un desafío.
    - Tiempo de carga inicial más largo.
    - Dependencia de JavaScript para el funcionamiento.

## SSR (Server Side Rendering)

- El renderizado del lado del servidor (SSR) es una técnica en la que el contenido de una página web se genera y se procesa en el servidor antes de enviarse al navegador del usuario. En SSR, cuando un usuario solicita una página web, el servidor ejecuta el código necesario para construir la página completa, incluyendo el HTML, CSS y JavaScript, y luego envía esa página ya renderizada al cliente. Esto permite que el contenido esté disponible de inmediato para el usuario y mejora la optimización para motores de búsqueda (SEO).

### Ejemplo

- Esto seria como un refrigedor de una maquina expendedora que tiene todos los sabores de helado ya preparados y listos para servir. Cuando alguien quiere un helado, simplemente selecciona el sabor y la máquina le entrega el helado ya hecho. 

### Ventajas:
    - Mejor SEO.
    - Contenido disponible de inmediato.
    - Mejor rendimiento en conexiones lentas.

### Desventajas:
    - Mayor carga en el servidor.
    - Tiempo de respuesta puede ser más lento.
    - Complejidad en la configuración y el desarrollo.

## Y donde entra Next js en todo esto?

- Next js nos permite combinar todas estas ventajas en una sola aplicación. Podemos tener paginas estáticas, podemos tener renderizado del lado del cliente y del lado del servidor, todo en una misma aplicación. Esto nos da una flexibilidad enorme a la hora de desarrollar aplicaciones web, ya que podemos elegir la mejor estrategia para cada parte de nuestra aplicación según nuestras necesidades.
